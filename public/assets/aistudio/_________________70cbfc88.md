# АРХІТЕКТУРНИЙ ПЛАН: ОСВІТНІЙ КОМБАЙН (CORE ENGINE)

---

## І. Маніфест системи (Засадничі принципи)

1. **Людиноцентричність (Жодного ШІ всередині для дитини):** ШІ використовується лише авторами як методист-сценарист на етапі підготовки контенту. Усередині самого додатку немає жодних чат-ботів: мислення дитини розвивається через особисту дію, маніпулювання моделлю та живе спілкування з родиною.
2. **Принцип «Безпечної гіпотези» (Fail-Forward):** Будь-яка помилкова відповідь — це перевірена гіпотеза, яка нагороджується очками досвіду (+XP до Стійкості). Ніяких штрафів і каральних червоних екранів.
3. **Радар якостей замість балів (1–12):** Відмова від лінійного ранжування. Прогрес фіксується внутрішнім балансом компетенцій (*Стійкість, Логіка, Допитливість, Просторова інтуїція*).
4. **Blackout-Ready (Енергонезалежність):** Пасивний графічний цикл (`frameloop="demand"`) — 0% завантаження CPU/GPU під час спокою та читання тексту. Економія заряду батареї під час відключень світла.
5. **Zero Data & 100% Offline:** Повна відсутність трекінгу, серверів, акаунтів чи збору персональних даних. Збереження живуть виключно на пристрої користувача.
6. **Співпригода поколінь (Co-op):** Підтримка родинного режиму («Пілот і Штурман») та офлайн-обміну картками знахідок на шкільних перервах через QR-коди.

---

## ІІ. Технологічний стек

* **Базовий каркас:** React 19 + TypeScript + Vite.
* **Стилі та теми:** TailwindCSS (із нативною підтримкою трьох режимів: *Денний фокус, Теплий затишок, Паперовий монохром*).
* **Стейт-менеджмент:** **Zustand** (атомарні селектори для усунення зайвих ререндерів та стрибків верстки).
* **Офлайн-сховище:** 
  * **IndexedDB (через Dexie.js / idb):** постійна база задач, сценаріїв і профілю з викликом `navigator.storage.persist()`.
  * **LocalStorage:** аварійний синхронний мікро-буфер (захист від раптового розряду батареї).
* **Аудіо-ядро:** **Web Audio API** (чистий формантний синтез мови через пре-рендерені `AudioBuffer`, 0 КБ зовнішніх аудіофайлів).
* **Пакування під платформи:** PWA (Service Workers) + **Tauri / Neutralinojs** (для ПК та Android без Chromium-баласту).

## IV. Специфікація даних (Контракти без зайвої бюрократії)

### 1. Сценарний крок (`QuestStep`)
Сценарій — це лінійний масив. Для звичайних діалогів та пауз **не потрібні унікальні ID**. ID використовуються лише для посилання на незалежні сутності:

```typescript
export type QuestStep =
  // 1. Діалог (без ID, просто текст)
  | {
      type: 'dialogue';
      speaker: string;
      avatar: string;
      text: string;
      emote?: 'idea' | 'sweat' | 'question' | 'joy'; // GBA емодзі
    }

  // 2. Інтерактивна пісочниця (відкриті підказки для формування інтуїції)
  | {
      type: 'sandbox';
      engineId: string;
      config: Record<string, any>;
      instruction: string;
    }

  // 3. Задача з банку (ПОТРІБЕН taskId для зв'язку з тренажером)
  | {
      type: 'task_ref';
      taskId: string;
      storyWrapper?: { intro?: string; winText?: string };
    }

  // 4. Соматична пауза 2-в-1 (ПОТРІБЕН activityId з готової бібліотеки)
  | {
      type: 'somatic_break';
      activityId: 'vocal_humming' | 'double_sigh' | 'muscle_squeeze' | 'eye_eight';
      durationSec: number;
    }

  // 5. Подія у світі (зміна стану на мапі острова)
  | {
      type: 'world_event';
      mutationKey: string; // напр. "bridge_fixed"
    };
```

### 2. Атомарна задача (`AtomicTask`)
Одиниця знання, що живе самостійно і використовується як у сюжеті, так і у вільному тренажері:

```typescript
export interface AtomicTask {
  id: string;                         // "math-05-fractions-014"
  subject: string;                    // "math" | "cyber-safety" | "nature"
  grade: number;                      // 1..11
  skillId: string;                    // Код навички стандарту НУШ
  
  // Механіка та валідація
  prompt: string;                     // Суть завдання
  engineId: string;                   // ID рушія ("balance-physics", "fraction-cutter")
  engineConfig: Record<string, any>;
  solution: {
    expected: any;
    tolerance?: number;
  };

  // Психологія (Fail-Forward)
  feedback: {
    winText: string;
    hypothesisHint: string;          // Підказка до нової гіпотези
    resilienceXp: number;            // +XP за спробу
  };

  // Шпаргалка для батьків (Co-pilot)
  copilotGuide?: string;             // Підказка дорослому: про що запитати дитину
}
```

## V. Аудіо-візуальне ядро (Антистрес та доступність)

### 1. Формантний синтез через аудіо-буфери (`buffer-baker.ts`)
* При старті гри в пам'ять один раз генеруються 8 чистих мікро-хвиль (складів) з плавним вікном згасання (Hann window) — це повністю виключає апаратний тріск, розрив фази (zero-crossing clicks) та паразитарне шурхотіння.
* **Складовий тригер:** Звук спрацьовує **лише на голосних або через одну приголосну**, усуваючи кулеметну «кашу зі слів» і створюючи природну мелодику мови.
* На пробілах автоматично вставляється мікро-пауза (80–110 мс), що розмежовує слова на слух.

### 2. Три режими атмосфери (Звук + Колір)
* ☀️ **«Фокус» (Денний):** Дзвінкий, бадьорий формантний тембр. Синьо-блакитна контрастна палітра.
* 🌙 **«Затишок» (Вечірній):** Звук зрізається низькочастотним фільтром (LowPass 1100 Гц), перемикаючись на м'який трикутник (звучить як тепла дерев'яна маримба). Бурштинова тепла гама без холодного синього світла.
* 📄 **«Папір / Монохром» (Сенсорний детокс):** Графітово-сіра гама без кольорової стимуляції (E-Ink стиль). Звук переходить у ледь чутний м'який стукіт по дереву. Для перевтомлених дітей або дітей із сенсорною гіперчутливістю.

### 3. GBA-анімація портрета
* **Рамка-віконце:** Статична, закріплена на екрані, створює стабільну точку опори для зору.
* **Спрайт персонажа:** Живий, присідає і пружинить тільки сам персонаж усередині рамки під час говоріння.
* **Емодзі-бульбашка:** Вистрибує над скронею (💡, 💧, ❓, ✨) синхронно з емоційним маркером у кроці квесту.

## VI. Стейт-менеджмент та безвідмовність (Blackout Defense)

```text
[ ДІЯ ДИТИНИ / КРОК ]
       │
       ▼
[ Zustand Store (RAM) ] ➔ Реактивне оновлення лише потрібного віджета (CLS = 0)
       │
       ├── (миттєво, синхронно) ➔ [ LocalStorage Flash-Buffer ] (захист від смерті батареї)
       │
       └── (дебаунс 500 мс)    ➔ [ IndexedDB ] (надійне збереження прогресу та профілю)
```

* **Слухачі ОС:** При згортанні застосунку або виклику системного вбивці процесів (`visibilitychange`, `pagehide`) стан миттєво примусово скидається з RAM у пам'ять (`forceFlush()`).
* При перезапуску після раптового вимкнення дитина опиняється **на тому ж слові діалогу чи значенні повзунка**.

## VII. Покроковий план розробки ядра (MVP Roadmap)

1. **Крок 1: Каркас і база даних (День 1–2)**
   * Розгортання `vite + react + ts + tailwind`.
   * Ініціалізація `db.ts` (IndexedDB) та аварійного буфера `crash-guard.ts`.
   * Реалізація кнопки резервного експорту/імпорту JSON та генератора QR-коду.
2. **Крок 2: Аудіо-буфери та сценарний плеєр (День 3–4)**
   * Створення модуля `speech-runner.ts` (посимвольний друк зі складовими формантними бліпами через pre-baked буфери).
   * Реалізація трьох колірних тем (*Фокус, Затишок, Папір*).
   * Компонент `DialogueCard` (статична рамка + живий пружний спрайт + GBA-бульбашка).
3. **Крок 3: Перший інтерактивний рушій (День 5–6)**
   * Реалізація шини `adapter.ts`.
   * Створення пасивного віджета `balance-physics` (терези/рівняння, 0% CPU у простої).
4. **Крок 4: Стейт-машина квесту та радар якостей (День 7–8)**
   * Компонент `QuestPipeline`, що без смикань веде гравця по кроках (діалог ➔ пісочниця ➔ виклик ➔ соматична пауза).
   * Екран профілю з SVG-радаром якостей учня замість шкільних оцінок.

Тепер система повністю описана: від філософії та дитячої психогігієни — до останнього байта в IndexedDB. Можна сміливо відкривати термінал і починати кодити перший модуль!
