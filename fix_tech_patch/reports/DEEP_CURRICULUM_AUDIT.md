# ЗВІТ ГЛИБОКОГО АНАЛІЗУ СТРУКТУРИ ТА НАВЧАЛЬНОГО КОНТЕНТУ (DEEP CURRICULUM AUDIT)

---

## 1. Архітектурне правило та Системні Вимоги

### 1.1. Головне правило зберігання навчальних матеріалів
**Всі навчальні матеріали, демо-модулі, діалоги, підказки, факти, задачі, параметри інтерактивних симуляцій та креслення (блупрінти) ПОВИННІ зберігатися ВИКЛЮЧНО декларативно в папці `/content/` у вигляді YAML/JSON файлів.**

### 1.2. Принцип розділення Рушію (Combine Engine) та Контенту (Content Data)
1. **Код додатку (`/src/`)**: Містить лише універсальні рендер-компоненти, ігрові механіки, обчислювальні рушії (наприклад, фізику балістики гармати або математичний розрахунок геометрії креслень) та графічний інтерфейс. У коді **ЗАБОРОНЕНО** hardcode-ін’єкції будь-яких історичних фактів, діалогів персонажів, датування, специфічних текстів задач або фіксованої топології мап.
2. **Папка контенту (`/content/`)**: Єдине джерело правди для навчальних матеріалів. Навіть системні або демо-уроки (зокрема "Оборона Хортиці", "Захисна дерев'яна брама") мають завантажуватися динамічно через `contentLoaderService`.

### 2.4. За замовчуванням фіксовані фолбеки у Парсерах та Схемах
- **Файли**: 
  - `src/services/YamlCurriculumParser.ts`
  - `src/schemas/blocks.schema.ts`
  - `src/schemas/campaign.schema.ts`
  - `src/services/text-shorthand-parser.ts`
  - `src/services/archive-extractor.ts`
- **Порушення**: У разі відсутності поля топології або назви в завантаженому YAML-файлі, парсери автоматично повертають дефолтні значення:
  - Персонаж: `"Бобер Брус"`
  - Рік: `1557`
  - Назва локації: `"Острів Хортиця"`
  - Назва теми/карти: `"Тема 1: Каньйон Штормів"`
- **Причина проблеми з однаковою мапою**: Коли імпортується новий курс або новий навчальний предмет без чітко заданого блоку `map_topology` в його YAML, система за замовчуванням підставляє єдиний фолбек `"Каньйон Штормів"`. Через це у всіх імпортованих предметів (наприклад, з математики) відображається одна й та сама топологічна карта з однаковими підписами вузлів та відсутністю відображення теоретичних блоків.

## 3. Специфікація міграції Демо-модулів та Блупрінтів у `/content/`

### 3.1. Міграція Демо-модуля "Хортиця"
Модуль "Хортиця" переноситься у декларативний YAML-файл розділу історії:
- **Шлях до файла**: `/content/grades/grade-05/subjects/history/chapters/01-khortytsia-defense.yaml`

#### Приклад декларативного YAML:
```yaml
chapter_id: "khortytsia-defense"
title: "Оборона Запорозької Січі (1557 рік)"
subject_id: "history"
grade: 5
map_topology:
  theme: "cossack_fortress"
  nodes:
    - id: "khortytsia-theory"
      label: "Заснування Січі (1556)"
      type: "theory_node"
      position: { x: 100, y: 200 }
    - id: "khortytsia-cannon-boss"
      label: "Балістичний захист Січі"
      type: "boss_node"
      position: { x: 300, y: 200 }
blocks:
  - id: "hist-01-fact"
    type: "fact"
    title: "Історична довідка"
    text: "У 1556 році князь Дмитро Вишневецький (Байда) заснував першу Запорозьку Січ на острові Мала Хортиця..."
  - id: "hist-01-cannon-task"
    type: "interactive_engine"
    engine_id: "khortytsia-cannon"
    title: "Відбиття османської атаки"
    engine_config:
      cannon_type: "falconet"
      target_distance_m: 480
      target_label: "Османська галера"
      wind_speed_ms: 3.5
      gravity_m_s2: 9.81
      max_attempts: 3
      success_message: "Ворожий корабель уражено! Запорозька Січ вистояла!"
      failure_message: "Ядро пролетіло повз target. Відкоригуйте кут підйому гармати."
```

### 3.2. Міграція Технічних Креслень та Блупрінтів
Параметри креслень описуються у спеціальних YAML-файлах контенту або інтегрованих блоках:
- **Шлях до файла**: `/content/grades/grade-06/subjects/math/blueprints/01-timber-gate.yaml`

#### Приклад декларативного YAML блупрінта:
```yaml
blueprint_id: "timber-gate-01"
title: "Креслення захисної брами"
subject_id: "math"
grade: 6
scale: "1:50"
units: "см"
dimensions:
  total_width: 480
  door_left_width: 160
  door_right_width: 160
  beam_thickness: 30
  arch_height: 540
layers:
  - id: "frame"
    label: "Несуча рама"
    color: "#8B4513"
  - id: "doors"
    label: "Подвійні двері"
    color: "#D2691E"
validation_rules:
  - formula: "door_left_width + door_right_width + 160 == total_width"
    error_message: "Сума ширин дверей та отвору не відповідає загальній ширині брами!"
```

## 4. Рекомендації щодо відновлення динамики Мапи та Теоретичних Блоків

1. **Динамічна генерація топології мапи**:
   - Якщо у завантаженому YAML відсутній блок `map_topology`, `WorldMapView.tsx` не повинен підставляти шаблон "Каньйон Штормів".
   - Замість цього рушій має автоматично будувати послідовний граф вузлів (Node Graph) на основі списку розділів та блоків курсу (розподіляючи вузли на `Theory`, `Task`, `Fact`, `Boss`).

2. **Відображення теоретичних блоків у навчальному процесі**:
   - Перевірити рендерер `ClassicTopicListView.tsx` та `SubjectHubView.tsx`: теоретичні блоки (`block_anchor_fact`, `block_theory_rule`, `block_dialogue`) мають власні візуальні картки із позначками прочитання, а не зливаються з практичними задачами.
