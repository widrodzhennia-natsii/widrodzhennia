## 1. Механіка 4 ролей із ротацією
Кожна команда з 2–4 учасників проходить спільну місію, змінюючи ролі на кожному новому етапі, щоб кожен учень спробував усі функції:
1. **Інженер** — керує симулятором, обчисленнями й технічною збіркою.
2. **Навігатор** — тримає умову задачі, карту проходження та орієнтири.
3. **Архіваріус** — перевіряє теорію, офлайн-довідник і формулює підсумок етапу.
4. **Економіст** — відповідає за спільний бюджет підказок, ресурси й ризики.

*(При грі вдвох ролі комбінуються попарно, при 3 гравцях одна роль чергується як спільна).*

## 2. Режими без центрального сервера
1. **Pass-and-Play (один пристрій по колу)**: чіткий екран передачі ходу з індивідуальною карткою поточної ролі.
2. **Режим класного проектора**: спільна задача й симуляція на великому екрані, фіксація відповідей команд локально або по черзі.
3. **Multi-phone Live Table (разові та тривалі квести)**:
   - Обмін ходами, станом кошика й підтвердженнями через компактні **QR-коди**;
   - Експериментальний канал **Web Bluetooth** (Progressive Enhancement для сумісних пристроїв без інтернету).

## 3. Питання для деталізації перед початком кодингу
- Формат компактного бінарного/JSON-пакета для QR-коду (обмеження обсягу під швидке зчитування камерою).
- Облік командних заслуг у персональному профілі кожного гравця (9 сильних сторін, зокрема «Співпраця» та «Лідерство»).
